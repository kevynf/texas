# Internationalization

Texas's UI translations use flat TOML locale tables in
`texas-app/assets/locales`. Locale files are embedded into the binary at
compile time, and English is the fallback locale.

## Runtime model

The supported UI language values are:

- `auto`: inspect the process locale environment and fall back to English;
- `en`: English;
- `zh-CN`: Simplified Chinese.

Use the shared `I18n` instance from `CommonData` in views. Ordinary UI text
uses `i18n.text(...)` or `i18n.text_signal(...)`; commands use
`command_text(...)`; settings use `setting_text(...)` and
`setting_value_text(...)`.

For Floem views, prefer a reactive producer such as
`label(i18n.text_signal("some.key"))` so a language change updates the view.
Calling `i18n.text(...)` while constructing a view snapshots the current
translation and is intended only for non-reactive values such as native dialog
titles or command metadata.

Keys may contain `{name}` placeholders that callers fill with
`i18n.text_with_args("some.key", "Fallback: {name}", &[("name", value)])`.
The fallback string is used when the key is missing from both locales and
receives the same substitutions. Native dialogs shown before any `I18n`
instance exists (the panic hook, startup failures) use the free function
`system_text("some.key")`, which looks the key up in the embedded tables using
the system locale.

`I18n` is kept in `CommonData` rather than Floem's context because the pinned
Floem context store is runtime-global, while Texas allows window tabs to have
independent workspace settings.

## Messages from the proxy

`texas-proxy` has no access to the reactive `I18n` instance. Proxy-originated
messages are currently plain strings: `ShowMessageParams::message`, the
`CoreNotification::ShowMessage` title, and `RpcError::message` are not
translation keys or localized text values. The UI displays these strings
directly; the translation-key checks do not cover proxy messages. Do not
assume that adding a locale entry will translate a proxy-originated message.

When a key is absent from the selected locale, lookup falls back to English.
If absent there too, `text` and `system_text` return the key itself, while
`text_with_args` uses the supplied fallback. New keys must be added to every
locale file; the `locale_files_have_matching_keys` test checks matching keys
and placeholders.

## Key structure

Use responsibility-based prefixes for ordinary UI text:

```text
common.<action>
menu.<item>
panel.<panel>
file-tree.<item>
terminal.<item>
git.<item>
command.<command-id>
```

Settings metadata follows one generated pattern:

```text
settings.item.<kind>.<field>.name
settings.item.<kind>.<field>.description
settings.value.<field>.<raw-value>
```

`<kind>` and `<field>` are the kebab-case configuration identifiers. The raw
configuration field and value are never translated when settings are written
back to disk; only their visible labels are localized.

## Translation checks

Translation consistency is enforced by tests in `texas-app/src/i18n.rs`, run
as part of `cargo test --workspace`:

- English and Simplified Chinese locale tables have matching key sets;
- every Texas and Floem command in the runtime command registry has a
  `command.<command-id>` entry in both locales;
- every settings field exposed by the metadata of `CoreConfig`,
  `EditorConfig`, `UIConfig`, and `TerminalConfig` has a
  `settings.item.<kind>.<field>.name` and `.description` entry in both
  locales, and each Simplified Chinese settings label/description contains
  Chinese text;
- literal keys in calls to `text(...)` and `text_signal(...)` in
  `texas-app/src` exist in the English locale. This regex-based check skips
  comments and string or character literal contents, but does not check
  `text_with_args(...)`, `system_text(...)`, dynamic keys, or proxy strings.

The command and settings checks read runtime metadata generated by the
`strum` and `structdesc` derives, so they follow the same filtered command
lists and skipped fields the running application uses. When a test fails,
add the missing key to both `texas-app/assets/locales/en.toml` and
`texas-app/assets/locales/zh-CN.toml`, keeping entries sorted
lexicographically, then fill in a real Simplified Chinese translation.

## Exclusions

Do not translate command IDs, configuration identifiers, raw configuration
values, paths, filenames, Git refs, logs, diagnostics, or user content. Fixed
configuration choices may have translated display labels, but their stored
values must remain unchanged.
